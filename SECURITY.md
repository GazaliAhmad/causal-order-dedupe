# Security Policy

## Supported Versions

Security fixes are provided for the latest `1.x` release line.

| Version | Supported |
| ------- | --------- |
| `1.0.x` | Yes |
| `<1.0`  | No |

If a future major or minor line becomes the active maintained release, this policy should be updated to reflect that change.

## Reporting a Vulnerability

Please do not report security vulnerabilities in public GitHub issues.

Use GitHub's private vulnerability reporting flow for this repository when available so details can be reviewed without public disclosure.

When reporting a vulnerability, include:

- a clear description of the issue
- affected package version(s)
- impact and expected risk
- reproduction steps or a minimal proof of concept
- any suggested mitigation or fix, if known

After a private report is received, the issue will be reviewed and triaged, and follow-up questions may be asked if more detail is needed to reproduce or validate the report.

## Scope

This policy applies to the published package and the source in this repository, including:

- `src/`
- packaging and release artifacts
- local runtime and test harness code used to evaluate dedupe behavior
